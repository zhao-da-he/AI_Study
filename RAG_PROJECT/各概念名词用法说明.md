## 一、Milvus 核心概念（10 个名词）

> 对应 [数据库.md L86-L99](./数据库.md#L86-L99)。

### 1. Collection（集合）—— 一张"向量表"

**类比**：传统数据库的"表"（Table）。

**通俗解释**：Milvus 里**所有向量都装在 Collection 里**，每个 Collection 就像 Excel 的一张大表，一行一条记录，一列一个字段。比如本项目里的 `t_collection01` 就是一张"半导体技术报告表"，每一行存一段技术文档。

**项目示例**：

```python
# documents/milvus_db.py L65-L76
if COLLECTION_NAME in client.list_collections():
    client.release_collection(collection_name=COLLECTION_NAME)  # 先释放
    client.drop_index(...)                                        # 再删索引
    client.drop_collection(collection_name=COLLECTION_NAME)      # 再删表
client.create_collection(collection_name=COLLECTION_NAME, schema=schema, index_params=index_params)
```

→ [documents/milvus_db.py L72-L76](../documents/milvus_db.py#L72-L76)

### 2. Field（字段）—— 表头的一列

**类比**：表的"列"（Column）。

**通俗解释**：一个字段定义一列数据的类型，比如"标题列""正文列""向量列"。本项目有 9 个字段：[id、text、category、source、filename、filetype、title、category_depth、sparse、dense](#二字段类型详解)。

### 3. Schema（表结构）—— 字段设计图

**类比**：建表时的 DDL 语句（`CREATE TABLE ...`）。

**通俗解释**：在建表之前，你要先告诉 Milvus「我要哪些字段、每个字段是什么类型、是不是主键」。这个"声明"就叫 Schema。

**项目示例**：

```python
# documents/milvus_db.py L22-L33
schema = client.create_schema()
schema.add_field(field_name='id', datatype=DataType.INT64, is_primary=True, auto_id=True)
schema.add_field(field_name='text', datatype=DataType.VARCHAR, max_length=6000, ...)
schema.add_field(field_name='dense', datatype=DataType.FLOAT_VECTOR, dim=512)
```

→ [documents/milvus_db.py L22-L33](../documents/milvus_db.py#L22-L33)

### 4. Index（索引）—— 书的目录

**类比**：书的目录，或字典的拼音检字表。

**通俗解释**：没有索引时，Milvus 要把查询向量和**每一个**存储向量都算一次距离（暴力扫描），百万级数据会非常慢。建了索引后，它会用某种"近似最近邻（ANN）"算法，只比较少量候选向量，速度快几十倍到上千倍。

**项目中的索引**：
- `sparse_inverted_index`（用于 BM25 稀疏向量）
- `dense_inverted_index`（用于 BGE 稠密向量，HNSW）

### 5. Partition（分区）—— 抽屉分格

**类比**：把一个大抽屉分成若干小抽屉。

**通俗解释**：当数据量很大时，可以按业务、时间等维度把 Collection 切成多个 Partition，查询时只搜其中一个抽屉，加快检索 + 方便管理。本项目未使用，属于进阶功能。

### 6. Entity（实体）—— 一行数据

**类比**：表的一行（Row / Record）。

**通俗解释**：一条 Entity 就是一条完整的数据记录，包含该行的所有字段值。比如本项目中一条 Entity = {id:1, text:"...", dense:[...], sparse:{...]}。

### 7. Function（字段函数）—— 自动计算器

**类比**：Excel 里的公式列。

**通俗解释**：你定义一个 Function，告诉 Milvus「输入字段 X，输出字段 Y，按某种算法计算」。当你 `insert` 数据时，Milvus 自动从 X 算出 Y 并填好，**你不用自己算**。

**项目示例**：

```python
# documents/milvus_db.py L35-L42
bm25_function = Function(
    name="text_bm25_emb",
    input_field_names=["text"],      # 从 text 字段读
    output_field_names=["sparse"],   # 算出 sparse 字段
    function_type=FunctionType.BM25,
)
schema.add_function(bm25_function)
```

→ [documents/milvus_db.py L35-L42](../documents/milvus_db.py#L35-L42)

效果：插入文档时，Milvus 自动调用 BM25 算法把 `text` 转成稀疏向量写入 `sparse`。

### 8. Search（搜索）—— 相似度匹配

**类比**：抖音的"猜你喜欢"。

**通俗解释**：给你一个查询向量，Milvus 返回最相似的 Top-K 条记录，可以叠加 filter 条件（如 `category == 'content'`）。

**项目示例**：

```python
# tools/retriever_tools.py
retriever = mv.vector_store_saved.as_retriever(
    search_type='similarity',
    search_kwargs={"k": 3, "score_threshold": 0.1, "ranker_type": "rrf", ...}
)
```

### 9. Query（查询）—— 按字段精确过滤

**类比**：Excel 的筛选功能。

**通俗解释**：纯标量过滤，不做向量计算。比如"找所有 `category == 'Title'` 的记录"。

**项目示例**：

```python
# documents/milvus_db.py L130-L134
result = client.query(
    collection_name=COLLECTION_NAME,
    filter="category == 'Title'",
    output_fields=['text', 'category', 'filename']
)
```

→ [documents/milvus_db.py L130-L134](../documents/milvus_db.py#L130-L134)

### 10. Consistency Level（一致性级别）—— 读到的数据有多"新"

**类比**：银行账户余额的"实时" vs "准实时"。

**通俗解释**：刚插入的数据，多久能被搜到？

| 级别 | 说明 | 延迟 |
| --- | --- | --- |
| **Strong** | 一定能读到最新数据 | 高 |
| **Session** | 同一会话内一致 | 中 |
| **Bounded** | 在限定时间内一致 | 低 |
| **Eventually** | 最终一致，最快 | 最低 |

**项目使用**：

```python
# documents/milvus_db.py L85
consistency_level="Strong"
```

→ [documents/milvus_db.py L85](../documents/milvus_db.py#L85)

→ 保证刚插入的文档立刻可被检索到（适合开发调试）。

## 二、字段类型详解

> 对应 [数据库.md L101-L113](./数据库.md#L101-L113)。

### 2.1 `id` —— INT64 主键

```python
# documents/milvus_db.py L23
schema.add_field(field_name='id', datatype=DataType.INT64, is_primary=True, auto_id=True)
```

| 参数 | 含义 |
| --- | --- |
| `INT64` | 64 位整数，范围 -9.2×10¹⁸ ~ 9.2×10¹⁸ |
| `is_primary=True` | 主键 |
| `auto_id=True` | Milvus 自动递增生成，不用我们传 |

**通俗解释**：就像每篇文章的"文章编号"，自动从 1 开始递增。

### 2.2 `text` —— VARCHAR + jieba analyzer

```python
# documents/milvus_db.py L24-L25
schema.add_field(field_name='text', datatype=DataType.VARCHAR, max_length=6000,
                 enable_analyzer=True,
                 analyzer_params={"tokenizer": "jieba", "filter": ["cnalphanumonly"]})
```

| 参数 | 含义 |
| --- | --- |
| `VARCHAR` | 可变长字符串 |
| `max_length=6000` | 最长 6000 字符（防止单条太大） |
| `enable_analyzer=True` | 开启分词器（让 BM25 能按词索引） |
| `tokenizer="jieba"` | 用 jieba 中文分词 |
| `filter=["cnalphanumonly"]` | 只保留中英文字母和数字（过滤标点、空格） |

**通俗解释**：
- `enable_analyzer=True` 告诉 Milvus"这段文字会被用来做全文检索，请先帮我分词"；
- `jieba` 是中文里最常用的分词工具，把"今天天气真好"切成 `["今天", "天气", "真好"]`；
- `cnalphanumonly` 过滤掉标点、空格、emoji 等。

### 2.3 元数据字段：`category` / `source` / `filename` / `filetype` / `title` / `category_depth`

```python
# documents/milvus_db.py L26-L31
schema.add_field(field_name='category', datatype=DataType.VARCHAR, max_length=1000)
schema.add_field(field_name='source', datatype=DataType.VARCHAR, max_length=1000)
schema.add_field(field_name='filename', datatype=DataType.VARCHAR, max_length=1000)

```

| 字段 | 通俗解释 | 项目取值 |
| --- | --- | --- |
| `category` | 是标题还是正文 | `'Title'` / `'content'` |
| `source` | 来源 | `'tech_report'` 等 |
| `filename` | 文件名 | `'operational_faq.md'` |
| `filetype` | 文件类型 | `'md'` |

### 2.4 `sparse` —— SPARSE_FLOAT_VECTOR 稀疏向量

```python
# documents/milvus_db.py L32
schema.add_field(field_name='sparse', datatype=DataType.SPARSE_FLOAT_VECTOR)
```

**什么是稀疏向量**？

想象一个 **超大词典**（比如 100 万个词），每个文档只对应其中几个词：

```
向量位置 0: 0.0   （词"人工智能"）
向量位置 1: 0.0   （词"机器学习"）
向量位置 58213: 3.7（词"光刻机" ← 这条文档有）
向量位置 102934: 1.2（词"清洗技术" ← 这条文档也有）
其他位置: 0.0 ...
```

只有**出现过的词**才有非零值，所以叫"稀疏"（大部分都是 0）。

存储方式：Milvus 只存 `(index, value)` 对，节省空间。

**怎么生成的**？—— 通过上文提到的 BM25 Function 自动算，不用我们手动算。

### 2.5 `dense` —— FLOAT_VECTOR(512) 稠密向量

```python
# documents/milvus_db.py L33
schema.add_field(field_name='dense', datatype=DataType.FLOAT_VECTOR, dim=512)
```

**什么是稠密向量**？

由 Embedding 模型（如 BGE）生成，**每个位置都有值**：

```
[0.023, -0.118, 0.452, 0.087, -0.339, ..., 0.211]   # 共 512 个
```

| 项 | 含义 |
| --- | --- |
| `FLOAT_VECTOR` | 浮点数向量 |
| `dim=512` | 维度 512（BAAI/bge-small-zh-v1.5 的输出维度） |

**为什么叫"稠密"？** 因为几乎每个位置都有值，跟稀疏向量相反。

**怎么生成的**？—— 通过 `Milvus(embedding_function=bge_embedding, ...)` 自动调用：

```python
# documents/milvus_db.py L80-L88
self.vector_store_saved = Milvus(
    embedding_function=bge_embedding,  # ← 插入时自动调用
    ...
)
```

## 三、索引类型详解

> 对应 [数据库.md L115-L121](./数据库.md#L115-L121)。

### 3.1 HNSW（Hierarchical Navigable Small World）

**用途**：稠密向量检索

**通俗解释**：

想象你在一个**大城市**找一家咖啡店，有两种方式：
- **方式 A（暴力扫描）**：挨家挨户问"你这里有咖啡吗？"
- **方式 B（HNSW）**：先跳到城市的最顶层（"我在哪个区？"），再到下一层（"我在哪条街？"），最后到具体门店。

HNSW 就是这种"**分层导航**"结构：

```
第 3 层（顶层）:  ●─────────────●  （少量节点，跳得远）
                  │             │
第 2 层（中层）:  ●────●────●───●────●  （中量节点）
                  │    │    │   │    │
第 1 层（底层）:  ●─●─●─●─●─●─●─●─●─●─●  （全量节点，找得准）
```

查询时**从顶层往下**，快速定位到大致范围，再在底层做精确比较。

**项目参数**：

```python
# documents/milvus_db.py L57-L63
index_params.add_index(
    field_name="dense",
    index_name="dense_inverted_index",
    index_type=IndexType.HNSW,
    metric_type=MetricType.IP,
    params={"M": 16, "efConstruction": 64}
)
```

| 参数 | 含义 | 通俗解释 |
| --- | --- | --- |
| `M=16` | 每个节点的邻居数 | 一家店记住 16 家相邻店 |
| `efConstruction=64` | 建索引时的搜索范围 | 建索引时"看得多准" |
| `MetricType.IP` | 内积距离 | 因为 BGE 已做 normalize，IP ≈ 余弦相似度 |

**优缺点**：

| 优点 | 缺点 |
| --- | --- |
| 精度高、查询快 | 内存占用大 |
| 支持动态增删 | 不适合超大规模（亿级以上） |

### 3.2 IVF_FLAT / IVF_PQ

**用途**：大规模稠密向量

**通俗解释**：

"IVF" = **Inverted File Index**（倒排文件索引）。先把所有向量用 K-Means 聚成 `nlist` 个簇：

```
簇 0: [v1, v5, v12, ...]    簇 1: [v3, v8, v22, ...]
簇 2: [v2, v7, v19, ...]    簇 3: [v4, v9, v15, ...]
...
```

查询时：
1. 先找到最近的 `nprobe` 个簇；
2. 只在这些簇里精确搜索。

→ 比 HNSW 内存占用小，但精度略低（因为只搜了部分簇）。

**PQ**（Product Quantization）：进一步压缩向量，把 512 个 float 压成 64 个字节，内存占用减少 8 倍以上。

**项目未使用**，但了解这个有助于选择更合适的索引。

### 3.3 SPARSE_INVERTED_INDEX（BM25 倒排索引）

**用途**：稀疏向量（BM25）

**通俗解释**：

跟搜索引擎的"倒排索引"一模一样：

```
词"光刻机"  →  [doc_3, doc_15, doc_27, ...]
词"清洗技术" →  [doc_5, doc_12, doc_27, ...]
词"EUV"     →  [doc_3, doc_8, ...]
```

查询"光刻机清洗"时，先查到 `光刻机 ∩ 清洗技术`，再用 BM25 公式打分排序。

**项目参数**：

```python
# documents/milvus_db.py L45-L56
index_params.add_index(
    field_name="sparse",
    index_name="sparse_inverted_index",
    index_type="SPARSE_INVERTED_INDEX",
    metric_type="BM25",
    params={
        "inverted_index_algo": "DAAT_MAXSCORE",
        "bm25_k1": 1.2,
        "bm25_b": 0.75
    }
)
```

| 参数 | 含义 | 通俗解释 |
| --- | --- | --- |
| `inverted_index_algo=DAAT_MAXSCORE` | 查询时的算法 | "跳跃式"跳过低分文档 |
| `bm25_k1=1.2` | 词频饱和度 | 1.2 是经验值（范围 1.2 ~ 2.0） |
| `bm25_b=0.75` | 文档长度归一化 | 0.75 是经验值（范围 0 ~ 1） |

**BM25 公式**（了解即可）：

```
score(D, Q) = Σ IDF(qi) × (f(qi,D) × (k1+1)) / (f(qi,D) + k1 × (1 - b + b × |D|/avgdl))
```

- `f(qi,D)`：词 qi 在文档 D 中的出现次数；
- `|D|`：文档长度；
- `avgdl`：平均文档长度；
- `IDF(qi)`：逆文档频率（越少见的词权重越高）。

**优缺点**：

| 优点 | 缺点 |
| --- | --- |
| 精确匹配关键词（型号/缩写） | 不懂语义（同义词召回差） |
| 速度快 | 仅支持 BM25 算法 |

### 3.4 三种索引对比

| 索引 | 适用场景 | 内存 | 精度 | 速度 |
| --- | --- | --- | --- | --- |
| **HNSW** | 稠密、千万级以内 | 大 | 高 | 快 |
| **IVF_FLAT** | 稠密、千万~亿级 | 中 | 中 | 中 |
| **IVF_PQ** | 稠密、亿级以上 | 小 | 中低 | 中 |
| **SPARSE_INVERTED** | 稀疏（BM25） | 小 | 关键词精确 | 快 |
