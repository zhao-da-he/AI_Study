## 一、硬件与运行环境：WSL2 / 云服务器 / 虚拟机 到底怎么选？

### 1.1 WSL2 是什么？

**WSL2 = Windows Subsystem for Linux 2**（Windows 上的 Linux 子系统第二代）

让 **Windows 系统里直接跑一个完整的 Linux 内核**，像打开一个 App 一样使用 Linux。

### 1.2 通俗类比

| 类比 | 解释 |
| --- | --- |
| 🏠 **Windows 电脑** | 一栋大楼 |
| 🪟 **WSL2 = 楼里的一间"Linux 房间"** | Linux 系统，跟其他房间共用基础设施 |
| 🚪 **进出的门** | 终端 |

### 1.3 三者核心对比

| 维度 | 🪟 **WSL2** | ☁️ **云服务器** | 💻 **虚拟机** |
| --- | --- | --- | --- |
| 跑在哪 | 你的电脑里 | 远端机房 | 你的电脑里 |
| 占用资源 | 几百 MB | 不占本地 | 几 GB（独占） |
| 启动速度 | 1~2 秒 | 远程秒开 | 30 秒~1 分钟 |
| 公网 IP | ❌ | ✅ | ❌ |
| 7×24 在线 | ❌ | ✅ | ❌ |
| 费用 | 免费 | 💰 按月付费 | 免费 |
| 适合场景 | 本地开发、学习 | 部署服务 | 测试、隔离 |

### 1.4 决策树

```
你要做什么？
├─ 在自己电脑上写代码 → ✅ WSL2
├─ 学 Linux / Docker    → ✅ WSL2
├─ 部署网站让别人访问   → ✅ 云服务器
├─ 跑大模型训练         → ✅ 云服务器 AutoDL
└─ 测试病毒、玩老游戏   → ✅ 虚拟机
```

## 四、向量数据库搭建方案：Milvus Lite vs Docker 详解

### 4.1 Milvus Lite 是什么？

> **Milvus Lite = Milvus 的"单机嵌入版"**
> 像手机 APP 一样装在电脑里就能用，**不需要 Docker、不需要服务器**。

| Milvus 版本 | 类比 |
| --- | --- |
| **Milvus Lite** | 📱 手机 APP（轻量） |
| **Docker Standalone** | 🏪 街边小店（中等） |
| **Milvus Cluster (K8s)** | 🏬 大商场（生产级） |

### 4.2 两种方式核心区别

| 维度 | 🪟 Windows + Milvus Lite | 🐧 WSL2 + Docker |
| --- | --- | --- |
| 在哪跑 | Windows 里直接跑 | WSL2 的 Linux 里跑 |
| 要装 Docker 吗 | ❌ 不要 | ✅ 要装 Docker |
| 要装 WSL2 吗 | ❌ 不要 | ✅ 要先装 WSL2 |
| Milvus 怎么启动 | 自动（pip install 即用） | 手动（`docker compose up -d`） |
| 数据库存哪 | 一个本地文件 `milvus.db` | Docker 容器里 |
| 能存多少数据 | 百万级向量 | 千万~亿级 |
| 适合谁 | 🟢 新手学习 | 🟡 进阶开发 |

### 4.3 两种方式架构图

**Milvus Lite 架构**：

```
┌─────────────────────────────┐
│   Windows 电脑               │
│  ┌──────────────────────┐  │
│  │  你的 Python 程序      │  │
│  │  + pymilvus 库         │  │
│  │       │               │  │
│  │       ↓ 调用          │  │
│  │  milvus.db 文件       │  │
│  └──────────────────────┘  │
└─────────────────────────────┘
```

**WSL2 + Docker 架构**：

```
┌─────────────────────────────┐
│   Windows 电脑               │
│  ┌──────────────────────┐  │
│  │  WSL2（Linux 内核）    │  │
│  │  ┌──────────────────┐ │  │
│  │  │  Docker           │ │  │
│  │  │  ┌─────────────┐  │ │  ← 3 个容器一起跑
│  │  │  │  Milvus      │  │ │
│  │  │  │  MinIO       │  │ │
│  │  │  │  etcd        │  │ │
│  │  │  └─────────────┘  │ │
│  │  └──────────────────┘ │
│  │       ↑ 端口 19530     │
│  │  ┌──────────────────┐ │
│  │  │  Python 程序      │ │
│  │  └──────────────────┘ │
│  └──────────────────────┘  │
└─────────────────────────────┘
```

### 4.4 可以在 WSL2 中创建向量数据库吗？

**完全可以！** WSL2 里能装 Milvus 的方式有 3 种：

| 方式 | 难度 | 推荐 |
| --- | --- | --- |
| **WSL2 + Python + Milvus Lite** | ⭐ | ✅✅✅ 最简单 |
| **WSL2 + Docker + Milvus Standalone** | ⭐⭐ | ✅✅ 进阶 |
| **WSL2 + 多容器 + Milvus Cluster** | ⭐⭐⭐⭐ | ✅ 生产 |

### 4.5 推荐组合（按阶段）

| 阶段 | 在哪跑 | 用的工具 | 难度 |
| --- | --- | --- | --- |
| **1. 入门** | Windows | Milvus Lite | ⭐ |
| **2. 进阶** | WSL2 | Milvus Lite | ⭐⭐ |
| **3. 实战** | WSL2 | Docker + Standalone | ⭐⭐⭐ |
| **4. 生产** | 云服务器 | Docker / K8s | ⭐⭐⭐⭐ |

## 五、核心疑问：到底算不算"在 Windows 上构建"？

### 5.1 你的疑问

> "WSL2 里用 Milvus Lite，不还是相当于在 Windows 上构建吗？"

**答：不是的！**

### 5.2 严格区分归属

| 维度 | Windows + Lite | WSL2 + Lite |
| --- | --- | --- |
| **Python 解释器** | Windows 版（python.exe） | **Linux 版**（python3） |
| **进程** | Windows 进程 | **Linux 进程** |
| **文件路径** | 反斜杠 `C:\xxx` | **正斜杠** `/home/xxx` |
| **命令** | PowerShell/CMD | **bash/shell** |
| **部署到云服务器** | 要改很多东西 | **几乎不用改** |
| **学 Linux** | ❌ 没学 | ✅ **顺便学了** |

### 5.3 Milvus Lite 跟 Milvus 服务端的区别

| | **Milvus 服务端** | **Milvus Lite** |
| --- | --- | --- |
| 运行方式 | 单独进程（监听端口） | 跑在**你的 Python 程序内部** |
| 操作系统 | ❌ 只支持 Linux/Mac | ✅ **Windows / Linux / Mac 都能跑** |
| 类比 | 📞 **客服热线** —— 你得打电话 | 🧠 **你自己的脑子** —— 直接用 |

### 5.4 重新解读"Windows 不方便"

> ❌ **不能这样说**："Windows 上构建向量库有很多缺点"
>
> ✅ **应该这样说**："Windows 上**部署生产级的 Milvus 服务**比较麻烦，**学习和开发阶段用 Milvus Lite 完全没问题**"

## 七、CRUD 不是 GPU 吗？

### 7.1 CRUD 是什么？

> **CRUD = Create（创建）、Read（读取）、Update（更新）、Delete（删除）**
> 数据库的"增删查改"四种基本操作

| CRUD 操作 | 英文 | 类比（图书馆） |
| --- | --- | --- |
| **C**reate | 创建 | 📚 新书上架 |
| **R**ead | 读取 | 🔍 查找图书 |
| **U**pdate | 更新 | ✏️ 修改信息 |
| **D**elete | 删除 | 🗑️ 下架图书 |

### 7.2 GPU 是什么？

> **GPU = Graphics Processing Unit（图形处理器）**
> 原本是显卡的核心，**现在被广泛用于 AI 计算**

### 7.3 CRUD vs GPU 对比

| 维度 | **CRUD** | **GPU** |
| --- | --- | --- |
| 是什么 | 操作类型（增删查改） | 硬件 |
| 跟谁有关 | 数据库/程序逻辑 | 硬件加速 |
| 需要显卡 | ❌ | ✅ |
| 跟 RAG 关系 | RAG 必备操作 | RAG 可选 |

### 7.4 Milvus 用 GPU 吗？

**默认用 CPU，GPU 是可选的加速选项**。

- **Milvus Lite**：✅ CPU，❌ 不支持 GPU
- **Milvus Standalone**：✅ CPU，可选 GPU（需装 GPU 版镜像）
- **Milvus Cluster**：✅ CPU，可选 GPU（生产环境）

### 7.5 本项目用 CPU

[llm_models/embeddings_model.py](../llm_models/embeddings_model.py)：

```python
bge_embedding = HuggingFaceEmbeddings(
    model_name="BAAI/bge-small-zh-v1.5",
    model_kwargs={"device": "cpu"},         # ← 用 CPU
)
```

> 本项目**全程 CPU**，不需要 GPU。

## 八、LangChain RAG 项目核心库完全讲解

### 8.1 BAAI/bge-small-zh-v1.5（HuggingFaceEmbeddings）

> **BGE = 一个把"中文"翻译成"机器能懂的数字"的小工具**

| 类比 | 解释 |
| --- | --- |
| 🈶 **中文翻译官** | 把中文句子翻译成"机器密码" |
| 📏 **small** | 模型小、跑得快 |
| 🇨🇳 **zh** | 专门翻译中文 |
| 📦 **BAAI** | 北京智源研究院 |

**翻译结果**（512 个数字）：

```
"什么是 EUV 光刻机？" 
   ↓ BGE 翻译
[0.12, -0.33, 0.87, -0.05, 0.23, ..., 0.45]
```

### 8.2 OpenAIEmbeddings

> **OpenAIEmbeddings = OpenAI 公司的"翻译服务"**（按字数收费）

| | **BGE** | **OpenAIEmbeddings** |
| --- | --- | --- |
| 价格 | **免费** | 💰 收费 |
| 维度 | 512 | 1536 |

### 8.3 unstructured / UnstructuredMarkdownLoader

> **Unstructured = 一台"高级扫描仪"**，把任何文档拆成"零件"

```
operational_faq.md
   ↓ UnstructuredMarkdownLoader
Document(分类="标题", 内容="...", 元数据={...})
Document(分类="段落", 内容="...", 元数据={...})
Document(分类="列表", 内容="...", 元数据={...})
```

### 8.4 langchain_experimental.SemanticChunker

> **SemanticChunker = 智能切刀**，按"语义"切文本，而不是按"字数"

```
句1 ──→ 句2 ──→ 句3 ──→ 句4
 小距离   小距离   ↑↑↑ 大距离！切！
   ↓       ↓       ↓
  段落1   段落1   段落2
```

### 8.5 langgraph.StateGraph

> **StateGraph = 流水线设计图**，把复杂任务画成图

```
用户提问 → [路由] → [检索] → [生成] → [评估] → END
```

| 类比 | 解释 |
| --- | --- |
| 🏭 **工厂流水线** | 每个工人做一件事 |
| 📋 **工作流程图** | 方框=做什么，箭头=下一步 |

### 8.6 mcp.server.fastmcp + langchain_mcp_adapters

> **MCP = "工具出租店的标准接口"**，让所有 AI 都能即插即用各种工具

| 名字 | 是什么 | 类比 |
| --- | --- | --- |
| **MCP** | 通信协议 | USB-C 接口标准 |
| **mcp.server.fastmcp** | 服务端工具包 | 卖工具的"店家" |
| **langchain_mcp_adapters** | 客户端适配器 | "借工具"的人 |

```ini
OPENAI_API_KEY=sk-abc123def456
```

### 8.8 7 个核心库一句话总结

## 九、StateGraph 编排、REPL、状态定义、聊天界面 通俗讲解

### 9.1 StateGraph 编排

> **StateGraph 编排 = 把"客服要做的事"画成一张流程图**

| 类比 | 解释 |
| --- | --- |
| 🏭 **工厂流水线** | 每个工位做一件事，工位之间用传送带连起来 |
| 📋 **工作流程图** | 方框=做什么，箭头=下一步去哪 |

```python
workflow = StateGraph(GraphState)
workflow.add_node("retrieve", retrieve)         # 资料员
workflow.add_node("generate", generate)         # 写手
workflow.add_edge("retrieve", "generate")       # 连传送带
graph = workflow.compile()                        # 流水线组装好
```

### 9.2 REPL 是什么？

> **REPL = Read-Eval-Print Loop**（读 → 执行 → 打印 → 循环）

| 类比 | 解释 |
| --- | --- |
| 💬 **微信聊天** | 一问一答 |
| 🗣️ **跟客服对讲机** | 一说一句，回一句 |

```python
while True:                                       # 死循环 = 一直对话
    question = input('用户：')                    # Read
    for output in graph.stream(...):              # Eval
        ...
    print(value["generation"])                    # Print
```

### 9.3 状态定义的作用

> **状态定义 = 流水线上传递的"工件夹"**，规定里面装什么数据

```python
class GraphState(TypedDict):
    question: str              # 用户问题
    transform_count: int       # 改写次数
    generation: str            # AI 生成的答案
    documents: List[Document]  # 检索到的文档
```

### 9.4 聊天界面 = 打开外部网页吗？

**是的，但不完全准确。** Gradio 启动后会在**浏览器打开一个网页**，但这个网页是**你的电脑提供的**。

```python
instance.launch(debug=True)
# 输出：Running on local URL:  http://127.0.0.1:7860
```

| URL | 含义 |
| --- | --- |
| `http://localhost:7860` | 只能你自己访问 |
| `http://127.0.0.1:7860` | 同上（IP 写法） |
| `http://192.168.1.100:7860` | 局域网里其他人能访问 |

让外网能访问：

```python
instance.launch(server_name="0.0.0.0", server_port=7860)
```

### 9.5 4 个概念总结

| 概念 | 类比 | 一句话 |
| --- | --- | --- |
| **StateGraph 编排** | 工厂流水线设计图 | 把 AI 任务画成流程图 |
| **REPL** | 终端微信聊天 | 读→执行→打印→循环 |
| **状态定义** | 流水线上的工件夹 | 规定传递的数据结构 |
| **Gradio 聊天界面** | 自己电脑开的小卖部 | 浏览器访问 localhost:7860 |

```python
def _print_event(event, _printed, max_length=1500):
    # 1. 取出最后一条消息
    message = event["messages"][-1]
    
    # 2. 避免重复打印
    if message.id not in _printed:
        msg_repr = message.pretty_repr(html=True)
        
        # 3. 太长就截断
        if len(msg_repr) > 1500:
            msg_repr = msg_repr[:1500] + " ... （已截断）"
        
        print(msg_repr)
        _printed.add(message.id)
```

## 二十一、milvus_db.py 中三句关键参数的作用

```python
builtin_function=BM25BuiltInFunction(),       # 第1句
vector_field=['dense', 'sparse'],              # 第2句
connection_args={"uri": MILVUS_URI}            # 第3句
```

### 第 1 句：`BM25BuiltInFunction()`

> **告诉 Milvus：插入数据时自动用 BM25 算法把 text 字段转成稀疏向量**

| 没有这行 | 有这行 |
| --- | --- |
| 要自己手动转稀疏向量 | Milvus 自动算 |

### 第 2 句：`vector_field=['dense', 'sparse']`

> **告诉 Milvus：同时用 dense 和 sparse 两个向量字段做检索（混合检索）**

| 写法 | 检索方式 |
| --- | --- |
| `['dense']` | 只用稠密向量（语义检索） |
| `['sparse']` | 只用稀疏向量（关键词检索） |
| `['dense', 'sparse']` | **混合检索（RRF 融合）** ✅ |

### 第 3 句：`connection_args={"uri": MILVUS_URI}`

> **告诉 LangChain "去哪台机器的哪个端口"找 Milvus**

| 写法 | 含义 |
| --- | --- |
| `'http://1.95.116.112:19530'` | 远程服务器 |
| `'http://localhost:19530'` | 本地 Docker |
| `'./milvus.db'` | 本地文件（Milvus Lite） |

### 缺任何一句会怎样？

| 缺哪句 | 后果 |
| --- | --- |
| 缺 `builtin_function` | sparse 字段没值，**只能用稠密检索** |
| 缺 `vector_field` | 检索报错或只用第一个字段 |
| 缺 `connection_args` | **连不上数据库**（最严重） |

## 二十二、多进程 Pipeline 完整执行步骤

### 22.1 为什么用多进程？

```
单进程：解析 + 写入 串行
多进程：解析 + 写入 同时进行（速度翻倍）
```

### 22.2 两个进程的分工

| 进程 | 角色 | 任务 |
| --- | --- | --- |
| **解析进程** | 📖 阅读员 | 读 .md → 拆零件 → 放上传送带 |
| **写入进程** | 📦 打包员 | 从传送带拿 → 写入 Milvus |

### 22.3 完整执行时间线

```
时间     解析进程              传送带（队列）          写入进程
────────────────────────────────────────────────────────────────
T0      启动                   空                      启动
T1      扫描到文件A             空                      等待
T2      解析文件A...            空                      等待
...
T6      解析文件C...            [20 个 Doc]             等待
T7      攒够 20 个！推上传送带   [20 个 Doc]              拿！开始写
T8      解析文件D...            [空]                    写入 Milvus...
T9      解析文件E...            [空]                    写入中...
...
T_end   所有文件解析完          空                      等待
T_end+1 推 None（下班信号）     None                    收到！下班
```

### 22.4 7 个执行步骤

```
Step 1: 主进程启动 → 创建 Queue
Step 2: 主进程建表（create_collection）
Step 3: 创建两个子进程，但不启动
Step 4: parser_proc.start() + writer_proc.start()
Step 5: 解析 + 写入 同时进行
Step 6: 解析进程发 None 暗号 → 写入进程 break
Step 7: 主进程结束
```

### 22.5 Windows 特别注意事项

> ⚠️ **必须用 `if __name__ == '__main__':`**，否则 Windows 上会无限递归

## 二十四、web_search_node.py 的返回值为什么有 documents 和 question？

### 24.1 一句话回答

> **LangGraph 节点返回的字典，就是"要更新到 state 里的字段"**
> - 返回 `documents` → 更新 `state["documents"]`
> - 返回 `question` → 更新 `state["question"]`
> - **没返回的字段保持不变**

### 24.2 代码

```python
def web_search(state):
    question = state["question"]
    docs = web_search_tool.invoke({"query": question})
    web_results = "\n".join([d["content"] for d in docs])
    web_results = Document(page_content=web_results)

    return {"documents": web_results, "question": question}
```

### 24.3 为什么 question 要原样返回？

| 原因 | 解释 |
| --- | --- |
| **下游节点要用** | `question` 是很多下游节点的"输入" |
| **明确表达意图** | 告诉 LangGraph："我要更新这些字段" |
| **防御性写法** | 万一上游的 question 变了，这里强制一致 |
| **代码可读性** | 看返回值就知道动了哪些字段 |

### 24.4 部分更新机制

```python
# 当前 state = {"A": 1, "B": 2, "C": 3}
# 返回 {"B": 20}
# 更新后 = {"A": 1, "B": 20, "C": 3}    ← 没返回的字段不动
```

### 25.2 3 种典型路径

#### 路径 1：知识库里有相关文档（最常见）


#### 路径 2：知识库查不到，改写问题再查

```
retrieve → grade（无相关）→ transform_query → retrieve → grade → generate → END
```

| 答案质量 | 答非所问 |

### 25.4 三大特点

1. **自评估（Self-RAG）**：LLM 自己当评委
2. **路由分发**：不同问题走不同路径
3. **自适应改写**：查不到时自动改写，最多 2 次
