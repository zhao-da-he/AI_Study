## 一、什么是向量数据库

### 1.1 一句话定义

**向量数据库（Vector Database）** 是一种专门用于存储、索引和检索**高维向量（Embedding）** 的数据库。向量通常由 Embedding 模型（如 BGE、OpenAI text-embedding-3）将文本、图片、音频等非结构化数据转换而来。

### 1.2 为什么需要向量数据库

| 场景 | 传统数据库 | 向量数据库 |
| --- | --- | --- |
| 按 ID/标题精确查找 | ✅ 擅长 | ✅ 支持 |
| "找出和这段话最相似的 10 条记录" | ❌ 不擅长 | ✅ 核心能力 |
| 千万级向量毫秒级返回 | ❌ 全表扫描慢 | ✅ HNSW/IVF 等近似最近邻（ANN）索引 |

### 1.3 工作原理

```
原始文本 ──Embedding 模型──> 向量 [0.12, -0.33, 0.87, ...]
                                      │
                                      ▼
                                Milvus Collection
                                      │
                                      ▼
用户提问 ──Embedding 模型──> 查询向量 ──ANN 检索──> Top-K 相似文档
```

> 类比：传统数据库是"按主键查"，向量数据库是"按距离查"。

## 二、Milvus 是什么

[Milvus](https://milvus.io) 是一个**开源、云原生、高性能**的向量数据库，专为大规模向量相似度搜索设计。

### 2.1 核心特性

- **多种索引算法**：HNSW、IVF、Flat、DiskANN 等；
- **混合检索**：同时支持稠密向量 + 稀疏向量（BM25），通过 RRF/Weighted Ranker 融合；
- **标量过滤**：在向量检索时叠加 `filter` 表达式（如 `category == "content"`）；
- **多语言 SDK**：Python、Java、Go、Node.js、C++、Rust；
- **三种部署模式**：Milvus Lite（嵌入式）/ Standalone（单机）/ Cluster（集群）。

### 2.2 Milvus 在本项目中的位置

- 配置文件：[utils/env_utils.py](../utils/env_utils.py) 里的 `MILVUS_URI` 与 `COLLECTION_NAME`；
- 写入封装：[documents/milvus_db.py](../documents/milvus_db.py) 的 `MilvusVectorSave`；
- 写入入口：[documents/milvus_db.py](../documents/milvus_db.py) 的 `__main__` 与 [documents/write_milvus.py](../documents/write_milvus.py) 的多进程流水线；
- 检索封装：[tools/retriever_tools.py](../tools/retriever_tools.py)；
- 基础实验：[test_milvus/demo1.py](../test_milvus/demo1.py)、[test_vector/demo1.py](../test_vector/demo1.py)。

## 三、Milvus 的核心概念

| 概念 | 类比 | 说明 |
| --- | --- | --- |
| **Collection** | 表 | 存储一组同构向量的容器，本项目用 `t_collection01` |
| **Field** | 字段 | 向量字段、文本字段、元数据字段 |
| **Schema** | 表结构 | 定义字段名、类型、维度、是否主键 |
| **Index** | 索引 | 加速 ANN 检索的数据结构 |
| **Partition** | 分区 | 物理分片，按业务隔离 |
| **Entity** | 行/记录 | 一条数据 = 1 个 entity |
| **Function** | 字段函数 | 自动从原始字段生成向量字段（如 BM25 → sparse） |
| **Search** | 查 | 向量相似度检索，可叠加 filter |
| **Query** | 查 | 纯标量过滤，不做向量计算 |
| **Consistency Level** | 一致性级别 | Strong / Session / Bounded / Eventually |

### 3.1 本项目用到的字段类型

参见 [documents/milvus_db.py L20-L33](../documents/milvus_db.py#L20-L33)：

| 字段 | 类型 | 作用 |
| --- | --- | --- |
| `id` | INT64 (PK, auto_id) | 主键 |
| `text` | VARCHAR(6000) + jieba analyzer | BM25 输入文本 |
| `category` | VARCHAR(1000) | 'Title' / 'content' |
| `source` / `filename` / `filetype` / `title` | VARCHAR | 元数据 |
| `category_depth` | INT64 | 标题层级深度 |
| `sparse` | SPARSE_FLOAT_VECTOR | BM25 稀疏向量（Function 自动生成） |
| `dense` | FLOAT_VECTOR(512) | BGE 稠密向量 |

### 3.2 索引类型选择

| 索引 | 适用 | 参数 | 优点 | 缺点 |
| --- | --- | --- | --- | --- |
| **HNSW** | 稠密向量 | `M=16, efConstruction=64` | 精度高、查询快 | 内存占用大 |
| **IVF_FLAT / IVF_PQ** | 大规模稠密 | `nlist=1024` | 内存友好 | 精度略低 |
| **SPARSE_INVERTED_INDEX** | 稀疏（BM25） | `k1=1.2, b=0.75` | 全文检索 | 仅支持 BM25 |

### 4.2 Linux 安装

#### 方式 A：Milvus Lite（最简单）

```bash
pip install pymilvus
# 使用本地文件
python -c "from pymilvus import MilvusClient; MilvusClient('./milvus.db')"
```

#### 方式 B：Docker Standalone（推荐生产）

```bash
# 1. 安装 Docker
sudo apt update
sudo apt install -y docker.io docker-compose

# 2. 下载 docker-compose.yml
wget https://github.com/milvus-io/milvus/releases/download/v2.5.6/milvus-standalone-docker-compose.yml -O docker-compose.yml

# 3. 启动
sudo docker-compose up -d

# 4. 查看日志
sudo docker-compose logs -f milvus-standalone
```

> Linux 上所有组件（etcd / MinIO / Milvus）都以容器方式运行，最稳定。

#### 方式 C：K8s（Helm Chart）

```bash
helm repo add milvus https://milvus-io.github.io/milvus-helm/
helm install my-milvus milvus/milvus --set cluster.enabled=true --namespace milvus --create-namespace
```

#### 方式 A：Milvus Lite（强烈推荐新手）

```bash
pip install pymilvus
# Apple Silicon 默认 arm64，运行无差异
```

### 4.4 Windows 安装

Windows 有 **3 种路线**，按推荐度排序：

#### 方式 A：Milvus Lite（✅ 强烈推荐新手）

```powershell
pip install pymilvus
python -c "from pymilvus import MilvusClient; MilvusClient('./milvus.db')"
```

Milvus Lite 是嵌入式 C++ 实现，**无需 Docker**，纯 Python 即可运行，是 Windows 下最省心的方案。

#### 方式 B：WSL2 + Docker（推荐进阶）

```powershell
# 1. 安装 WSL2
wsl --install

# 2. 安装 Ubuntu（默认）

# 3. 在 WSL2 Ubuntu 中按 Linux 方式安装 Docker
sudo apt update && sudo apt install -y docker.io
sudo service docker start

# 4. 拉取 Milvus standalone
wget https://github.com/milvus-io/milvus/releases/download/v2.5.6/milvus-standalone-docker-compose.yml -O docker-compose.yml
sudo docker-compose up -d
```

#### 方式 C：Docker Desktop for Windows

1. 安装 [Docker Desktop](https://www.docker.com/products/docker-desktop/)；
2. 设置 → Resources → WSL integration → 启用；
3. 同 macOS 方式 B 拉起 standalone。

#### ⚠️ Windows 注意事项

- **路径分隔符**：Python 代码中推荐用 `pathlib.Path` 或 `r'D:\data\milvus.db'`，**不要用 `/`**，避免反斜杠转义；
- **中文编码**：读取 Markdown 时显式 `encoding='utf-8'`，避免 Windows 默认 GBK；
- **多进程**：Windows 下 `multiprocessing` 必须放在 `if __name__ == '__main__':` 内（[write_milvus.py](../documents/write_milvus.py) 已正确处理）；
- **防火墙**：Docker Standalone 默认监听 `0.0.0.0:19530`，首次运行 Windows Defender 会弹窗询问是否放行；
- **PyTorch**：本项目用了 BGE Embedding 走 CPU，已在 [llm_models/embeddings_model.py](../llm_models/embeddings_model.py) 中设置 `device='cpu'`，Windows 下无需 GPU。

### 4.5 为什么三大系统会有差异

| 原因 | 说明 |
| --- | --- |
| **Milvus 核心是 Go/C++** | 需要跨平台编译，官方原生支持 Linux/macOS，Windows 依赖 WSL2 |
| **Docker 生态** | Linux 容器最轻量；macOS/Windows 需要虚拟化层（Docker Desktop / WSL2） |
| **文件系统差异** | Windows 的 NTFS 与 Linux 的 ext4 在处理大文件（>4GB）时有微妙差异 |
| **进程模型** | Windows 多进程用 spawn（慢），Linux/Mac 用 fork（快），所以 [write_milvus.py](../documents/write_milvus.py) 的多进程流水线在 Windows 上可能略慢 |
| **GPU 驱动** | CUDA 在 Linux 上最完善；Windows 也能用但安装步骤复杂 |

### 5.3 BM25 Function

```python
bm25_function = Function(
    name="text_bm25_emb",
    input_field_names=["text"],
    output_field_names=["sparse"],
    function_type=FunctionType.BM25,
)
schema.add_function(bm25_function)
```

效果：写入时 Milvus 自动读取 `text` 字段 → 调用内置 BM25 算法 → 把稀疏向量写入 `sparse` 字段。

### 5.4 索引参数

| 字段 | 索引类型 | 参数 |
| --- | --- | --- |
| sparse | SPARSE_INVERTED_INDEX (BM25) | `inverted_index_algo=DAAT_MAXSCORE`, `bm25_k1=1.2`, `bm25_b=0.75` |
| dense | HNSW | `M=16`, `efConstruction=64`, `metric=IP`（内积） |

## 七、混合检索（BM25 + 向量）原理与代码

### 7.1 为什么需要混合检索

| 检索方式 | 优势 | 劣势 |
| --- | --- | --- |
| **稠密向量**（BGE） | 语义相似，对同义词鲁棒 | 对专有名词/型号/缩写召回差 |
| **稀疏向量**（BM25） | 精确匹配关键词 | 不懂语义 |
| **混合（Hybrid）** | 兼顾两者 | 计算量略大 |

### 7.2 RRF 排序

Reciprocal Rank Fusion（倒数排名融合）公式：

```
RRF_score(d) = Σ 1 / (k + rank_i(d))
```

- `d`：候选文档；
- `rank_i(d)`：在第 `i` 路检索中的排名；
- `k`：常数（默认 60，Milvus 推荐 100）。

效果：两个检索结果都靠前的文档会获得更高分。

### 7.3 本项目的混合检索代码

[tools/retriever_tools.py](../tools/retriever_tools.py) 中：

```python
retriever = mv.vector_store_saved.as_retriever(
    search_type='similarity',
    search_kwargs={
        "k": 3,
        "score_threshold": 0.1,
        "ranker_type": "rrf",          # 关键：使用 RRF 融合
        "ranker_params": {"k": 100},
        'filter': {"category": "content"}   # 只查正文，过滤掉标题
    }
)
```

`test_milvus/demo1.py` 的 `test7` / `test8` / `test9` 还演示了 `pymilvus.AnnSearchRequest` + `RRFRanker(60)` 的手工混合检索写法。

## 九、常见问题 FAQ

### Q1：安装 pymilvus 报错 / 找不到 libpython

**Windows** 通常缺 Visual C++ 运行库，安装 [Microsoft Visual C++ Redistributable](https://aka.ms/vs/17/release/vc_redist.x64.exe)。
**Linux**：

```bash
sudo apt install -y libpython3-dev build-essential
```

### Q2：连接远程 Milvus 失败

```python
# 错误：MilvusException: <MilvusException: (code=2, message=Fail connecting to server on localhost:19530)>
```

排查：
1. Milvus 服务是否启动：`docker ps`；
2. 端口是否开放：`telnet <host> 19530`；
3. URI 协议：`http://` vs `tcp://`（pymilvus 默认 `http`，如有需要改 `tcp://`）。

### Q3：写入时 dim 不匹配

```
raise Exception: dimension mismatch
```

Embedding 维度必须与 schema 一致：
- 本项目 `dim=512`（BGE-small-zh）；
- OpenAI `text-embedding-3-small` 是 1536；
- 切换 Embedding 时必须改 [documents/milvus_db.py L33](../documents/milvus_db.py#L33) 的 `dim`。

### Q4：BM25 中文分词不准

修改 analyzer_params：

```python
analyzer_params={"tokenizer": "jieba", "filter": ["cnalphanumonly"]}
```

- `jieba`：默认中文分词；
- `cnalphanumonly`：只保留中英文字母和数字；
- 也可换 `"standard"` / `"ik"`（需安装 `pymilvus[model]`）。

### Q5：检索召回为空

- 检查 `filter` 是否过滤过多；
- 降低 `score_threshold`（从 0.5 → 0.1）；
- 确认 `category == 'content'`，而不是 `Title`。

### Q6：磁盘占用爆炸

- HNSW 索引会消耗大量内存；
- 建议单 Collection 数据控制在 1 亿以内；
- 更大规模请用 Milvus Cluster + DiskANN。

### Q7：Windows 多进程卡死

```python
# write_milvus.py 必须保证入口在 __main__ 内（已正确处理）
if __name__ == '__main__':
    ...
```

Windows 下 `multiprocessing` 默认使用 spawn，多个 `Process()` 会在 import 时重新执行整个脚本。

### Q8：如何删除整个 collection

```python
client.drop_collection(collection_name="t_collection01")
```

> [documents/milvus_db.py L65-L70](../documents/milvus_db.py#L65-L70) 已实现"存在则重建"的逻辑。
